Toll price first

A focused design for Approach A. Enter where you’re going and what you drive; get the exact toll, whether your FASTag annual pass covers it, and a few plain facts about the road. Built only on free and open data.

What the user gets

One screen, three answers: how much the toll is, whether the annual pass applies on this route, and a few facts about the road. Everything else is secondary.

If the user has no pass, the pass box flips to a savings answer instead: “With an annual pass you’d pay ₹640 instead of ₹1,075 on this trip. The pass pays for itself after about 8 such trips.” If the vehicle isn’t eligible (any commercial vehicle, or anything bigger than a car, jeep or van), it says so in one line and shows only the toll.

Scope

In

  • Toll for every vehicle class on NH, NE and state toll roads
  • One-way and return within 24 hours
  • Annual pass eligibility, coverage and trips used
  • Up to three routes: usual, lowest toll, toll-free (if one exists)
  • Three or four facts about the road from last year’s data

Out (for now)

  • Live traffic and exact travel time (estimate only)
  • Fuel cost and trip budgeting
  • Local-resident and monthly passes
  • Chat or voice interface (Approach B)
  • User accounts; nothing is stored about the user

Toll and pass rules

This is the product. Every rule below lives in the database as data, so a rule change is a data update, not a code release. The flowchart is page 2 of the Lucid document.

RuleHow the engine applies it
Charging pointsA route passes either point-based plazas (pay at each) or closed sections (pay by entry–exit pair). Both are “charging points”.
RateLooked up by point, vehicle class, journey type (single or return within 24 h) and travel date, so a trip after 1 April gets the new year’s rate.
Pass eligibilityOnly non-commercial cars, jeeps and vans with an active pass. Everyone else pays the full rate.
Where the pass worksOnly at points run by NHAI or MoRTH on NH and NE roads. Each point carries a pass_accepted flag; state roads such as the UP expressways, Samruddhi, Mumbai–Pune and Atal Setu are false.
Trip countingEach plaza crossing counts as one trip; a return through the same plaza counts as two. A closed section’s entry–exit pair counts as one trip, however many gantries it has.
Running out of tripsCovered points are taken in travel order until trips run out; later points are charged and marked “pass trips used up”.
Pass price₹3,075 for FY 2026–27, one year or 200 trips, whichever comes first. Stored per financial year.
Break-evenTrips to pay off = ₹3,075 ÷ (toll without pass − toll with pass) for this journey, shown only when the user has no pass.

Always show the reason. When the pass doesn’t apply at a point, the quote says why: not eligible, state road, or trips used up. That explanation is what users can’t easily get elsewhere.

Architecture

Small on purpose: one web app, one API service with the toll engine inside it, one database, and three self-hosted open-source map services. Data comes in through scheduled jobs with a human check on rate changes.

How one quote is computed

The API resolves the two places, then asks Valhalla for up to three routes: the usual one, one that prefers lower tolls, and one that avoids tolls entirely. For each route the engine finds the toll plazas within about 50 m of the route line (checking direction so the opposite carriageway isn’t counted) and the entry and exit points of any closed section. It prices each point, applies the pass rules in travel order, adds up the totals and attaches the route facts. Everything except the routing call is a few database lookups, so a quote should take well under a second after the route comes back.

Route insights

Keep it to three or four plain facts, each computed by summing a pre-built per-plaza table over the plazas on the route:

Fact shownComputed from
Number of toll points, and toll per km of tolled roadThe quote itself
Busiest plaza on the route last yearFASTag crossings per plaza, last financial year
FASTag toll collected at these plazas last yearFASTag value per plaza, last financial year
Share of car crossings that used the annual passAnnual pass report ÷ car-class crossings, NH plazas only

The hard part is matching IHMCL’s plaza names to TIS plaza IDs: do a fuzzy name match within the same state, then review the leftovers by hand once; after that only new plazas need attention. Label every fact with its period and “FASTag data”, because cash and exempt vehicles aren’t counted, and IHMCL notes its figures can change after reconciliation. If a route’s plazas aren’t in the reports, show nothing rather than a guess. Pipeline: page 3 of the Lucid document.

Build plan and risks

Step 1NH and NE plazas from TIS, car class, one-way, annual pass rules, usual route only. This alone answers the main question for most users.
Step 2All vehicle classes, return journeys, lowest-toll and toll-free routes.
Step 3Closed-section matrices for the busiest state expressways (UP, Maharashtra, Haryana, Gujarat), then the rest.
Step 4Route insights from IHMCL reports, once plaza name matching is done.

Accuracy is the brand. Keep a test set of a few hundred journeys with hand-checked totals from official notices and run it on every rate update. A wrong toll does more damage than a missing feature.

Scraping risk. TIS has no API and its pages can change. Watch every scrape for missing plazas or large rate jumps, and hold changes for review rather than publishing them automatically.

State coverage. Until a state road is curated, show its toll as “not yet available” on the route instead of leaving it out of the total silently.

Statistics licence. IHMCL publishes its reports freely but without an open licence; show derived figures with attribution, and ask IHMCL before redistributing the raw data.

Rates, pass rules and exclusions change; verify against NHAI, IHMCL and state notices before relying on any figure in production.
